# Nhật ký Mobile - 24 tháng 8 năm 2026

## Hôm nay tôi muốn làm gì?

Tập trung vào phần Backend Data/API theo kế hoạch tháng 8, nhưng vẫn kiểm tra tác động đến ứng dụng Flutter.

## Tôi đã làm được gì?

- Không đổi giao diện Home đang chạy ổn trên iOS Simulator.
- Xác nhận Mobile vẫn nhận response theo envelope `{ data, meta, error }`.
- Tạo model `WeeklyLeaderboard` và `LeaderboardRow`.
- Tạo repository gọi `GET /v1/leaderboards/weekly` và đọc response envelope.
- Tạo controller có trạng thái loading, dữ liệu, empty và lỗi/retry.
- Mở màn Leaderboard từ tab Explore trên Home.
- Thêm test cho API decoder và widget state.

## Tôi gặp khó khăn gì?

Lúc nối repository vào `MyApp`, test dùng fake Home repository bị lỗi vì app vẫn cố đọc `API_BASE_URL` rỗng để tạo Leaderboard repository thật.

## Tôi tháo gỡ ra sao?

Tôi sửa dependency construction: chỉ tạo API repository thật khi chạy production; test double thì không cần network.

## Tôi học được gì?

Mobile không nên tự lặp lại business rule của Backend. Khi API có response ổn định, Flutter chỉ cần hiển thị đúng trạng thái và phản hồi lỗi rõ ràng cho người dùng. Tôi cũng học được rằng tạo dependency quá sớm có thể làm test UI phụ thuộc vào môi trường local.

## Trạng thái thật

Màn Leaderboard Mobile đã hoàn thành phần UI và repository ở local test. Chưa chạy manual end-to-end trên simulator với Firebase token thật.

## Việc tiếp theo

Chạy trên iOS Simulator với Backend local, sau đó bổ sung workout log để kiểm tra cache leaderboard bị invalidation sau khi ghi dữ liệu.
