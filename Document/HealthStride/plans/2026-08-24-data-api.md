# Kế hoạch Data, Database và API tháng 8

## Mục tiêu học tập

Tôi muốn củng cố các phần mình còn yếu ở level M1 và M2 bằng một vertical slice có thể chạy được:

- Đọc `EXPLAIN ANALYZE` và tự chọn index.
- Hiểu migration `up/down` và cách rollback khi có lỗi.
- Làm cache-aside cho leaderboard với TTL, invalidation và chống cache stampede.
- Tự viết rate limit theo user bằng Redis sliding window.
- Chuẩn hóa mọi response về `{ data, meta, error }` và dùng OpenAPI/Swagger làm tài liệu API.

## Phạm vi đã làm trong PR này

1. Thêm index covering cho truy vấn lịch sử và leaderboard.
2. Chạy migration trên PostgreSQL Docker local.
3. Seed dữ liệu lặp lại được với ít nhất 1.000 user/workout.
4. Chạy ba truy vấn đại diện bằng `EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)`.
5. Ghi kết quả tại `evidence/performance/2026-08-24-after.md`.
6. Giữ cache leaderboard 60 giây, xóa cache sau khi ghi workout thành công và dùng lock Redis có token để chống stampede.
7. Giữ rate limit đã có: GET 100 request/phút, POST 10 request/phút theo user.

## Những điều chưa nói là đã xong

- Chưa triển khai Facebook và LINE OAuth trong scope tháng 8. Google/Firebase là provider đang dùng.
- Chưa có benchmark production. Số đo hiện tại chỉ là local với dữ liệu seed.
- Màn Leaderboard Flutter đã được nối vào tab Explore với loading, empty và retry state. Manual simulator với Firebase token thật vẫn là bước xác minh tiếp theo.

## Cách chạy lại

```bash
cd Backend
docker compose up -d
uv run alembic upgrade head
uv run python -m app.db.seed --users 1000
uv run python -m scripts.query_plans --output-dir ../Document/HealthStride/evidence/performance
uv run pytest -q
```
